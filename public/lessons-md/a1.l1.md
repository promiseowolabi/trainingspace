# A1.L1 — Derivatives as Sensitivity

_Track A1: Autograd from Scratch · ~14 min · trainingspace_

> Forget the calculus class. A derivative answers one engineering question — if I nudge this input, how much does the output move? — and you can measure it with two function calls.
The **derivative** of a function `f` at a point `x` is the ratio

```
how much f(x) changes
---------------------   for a very small nudge
  how much x changed
```

That is all. If `f'(x) = 6`, nudging `x` up by 0.001 moves `f` up by about 0.006. If it is −6, `f` moves *down* by about 0.006. If it is 0, `f` does not care about small changes to `x` at all. For training, read **f** as the loss and **x** as one parameter: the derivative says how sensitive the loss is to that parameter, and its sign says which way is downhill.

## Measure it

You do not need a formula to get a derivative. Nudge and measure:

```python
def forward_diff(f, x, h=1e-3):
    return (f(x + h) - f(x)) / h

def central_diff(f, x, h=1e-3):
    return (f(x + h) - f(x - h)) / (2 * h)
```

For `f(x) = x³` at `x = 2` the exact answer is `3x² = 12`. Measured in float64 on the reference laptop:

---

| step h | one-sided | error | central | error |
|---|---|---|---|---|
| 10⁻¹ | 12.61 | 6.1 × 10⁻¹ | 12.01 | 1.0 × 10⁻² |
| 10⁻³ | 12.006001 | 6.0 × 10⁻³ | 12.000001 | 1.0 × 10⁻⁶ |
| 10⁻⁵ | 12.0000600 | 6.0 × 10⁻⁵ | 12.0000000002 | 2.1 × 10⁻¹⁰ |
| 10⁻⁸ | 11.99999993 | 7.3 × 10⁻⁸ | 11.99999988 | 1.2 × 10⁻⁷ |
| 10⁻¹² | 12.00107 | 1.1 × 10⁻³ | 12.00107 | 1.1 × 10⁻³ |

Two lessons are in that table.

**Central differences converge much faster.** The one-sided error shrinks in proportion to *h*; the central error in proportion to *h²*, because the curvature errors on the two sides cancel. At h = 10⁻³ that is the difference between three correct digits and six.

**Smaller is not always better.** Below about 10⁻⁵ the error grows again. `f(x + h)` and `f(x − h)` agree in almost every digit, and subtracting two nearly equal floats leaves mostly rounding noise (float64 carries about 16 significant digits). At h = 10⁻¹² the noise dominates. In float32 — 7 digits — the sweet spot is near 10⁻³, which is why gradient checks run in float64 (A1.L5).

---

- **∝ h** — one-sided error (the first neglected Taylor term is (h/2)·f″(x))
- **∝ h²** — central error (the f″ terms cancel; the next is (h²/6)·f‴(x))
- **~10⁻⁵** — best h, float64 (measured on x³ at 2: error 2 × 10⁻¹⁰)
- **2 calls** — per parameter (central differences need f(x+h) and f(x−h) — for every parameter separately)

## Many inputs: partial derivatives and the gradient

A loss depends on every parameter at once. A **partial derivative** `∂L/∂w` is the same nudge-and-measure question asked about one input while the others are held still. Collect one partial derivative per parameter and you have the **gradient**, written ∇L: a vector with exactly as many entries as the model has parameters, the same shape as the parameters themselves.

The gradient has one more property that makes it the right thing to follow: of all directions you could move the parameters, **−∇L is the one in which the loss falls fastest** for a small step. That is why the update in T0.L1 is `p −= lr · g`.

## Where T0.L1's formulas came from

The line model's loss for one point is `(w·x + b − y)²`. Two rules you can check numerically do all the work:

- the derivative of u² with respect to u is **2u**;
- if `u` depends on `w`, multiply by how much `u` moves per unit `w` — here `x`. (That multiplication is the **chain rule**, and A1.L2 is entirely about it.)

So ∂/∂w of `(w·x + b − y)²` is `2·(w·x + b − y)·x`, and ∂/∂b is `2·(w·x + b − y)·1`. Average over the three points and you have T0.L1's `dL/dw` and `dL/db`.

---

```python
xs, ys = [1, 2, 3], [3, 5, 7]

def loss(w, b):
    return sum((w * x + b - y) ** 2 for x, y in zip(xs, ys)) / len(xs)

w, b, h = 0.0, 0.0, 1e-5
numeric_dw = (loss(w + h, b) - loss(w - h, b)) / (2 * h)
formula_dw = 2 / len(xs) * sum((w * x + b - y) * x for x, y in zip(xs, ys))
print(numeric_dw, formula_dw)   # -22.6666..., -22.6666...
```

---

> **[warning]** Nudging is exact enough, simple, and needs no calculus. It is also hopeless at scale: two loss evaluations **per parameter**. A model with 10⁸ parameters would need 2 × 10⁸ forward passes for one gradient. The next lesson shows how the chain rule gets all 10⁸ partial derivatives for the price of roughly one extra pass — and nudging becomes what it is best at: checking that those derivatives are right.

**Q1. For one parameter, ∂L/∂w = −40 and for another ∂L/∂v = 0.01. What do these tell you?**
   A. w should be decreased; v barely matters right now
   B. w should be increased a lot; v barely affects the loss at the current point
   C. w is a worse parameter than v
   D. The learning rate for w should be 4,000× smaller
   Answer: B — A negative derivative means increasing w decreases the loss, so the step p −= lr·g increases w. The magnitude 40 says the loss is very sensitive to w here. A derivative of 0.01 says small changes to v hardly move the loss at this point — not that v is useless in general.

**Q2. A colleague checks a float32 gradient with forward differences at h = 1e-8 and finds wild disagreement. Most likely cause?**
   A. The analytic gradient is wrong
   B. h is far too small for float32: f(x+h) − f(x) is mostly rounding error with about 7 significant digits — use float64, central differences and h around 1e-5
   C. Forward differences only work for linear functions
   D. h should be negative
   Answer: B — In float32, x + 1e-8 often equals x exactly for x of order 1, so the difference is zero or pure noise. Gradient checks are run in float64 with central differences, where h ≈ 1e-5 balances truncation error against rounding error.

**Q3. What shape is the gradient of a scalar loss with respect to a weight matrix of shape (768, 3072)?**
   A. a scalar
   B. (3072, 768)
   C. (768, 3072)
   D. (768,)
   Answer: C — There is one partial derivative per weight, so the gradient has exactly the parameter's shape: (768, 3072). This is the rule lab 02 checks for every operation — .grad always has the same shape as .data.

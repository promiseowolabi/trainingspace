# T0.L2 — Tensors and Shapes

_Track T0: The Training Contract · ~18 min · trainingspace_

> Half the bugs in training code are shape bugs, and most of them do not crash — numpy broadcasts the mistake into a plausible-looking wrong answer. Learn the one rule and the shape becomes the spec.
A **tensor** is an n-dimensional array of numbers that all have the same type. The word sounds like physics; the thing is a numpy `ndarray` (or a `torch.Tensor`, which is the same idea plus a device and an autograd tape). Three attributes describe one completely:

- **shape** — a tuple, one entry per dimension: `(32, 128, 768)`.
- **dtype** — what each element is: `float32` (4 bytes), `bfloat16` (2), `int64` (8).
- **the data** — `prod(shape)` elements, contiguous in memory.

So a `(32, 128, 768)` float32 tensor is 32 × 128 × 768 = 3,145,728 numbers and **12.6 MB**. You will compute that product a lot (T0.L4).

## The shape is the specification

In training code almost every tensor has a conventional shape, and reading the shape tells you what the tensor *is*:

| shape | name | meaning |
|---|---|---|
| `(B, d_in)` | a batch of inputs | B examples, d_in features each |
| `(d_in, d_out)` | a weight matrix | maps d_in features to d_out |
| `(B, T)` | a batch of token ids | B sequences of T tokens, integers |
| `(B, T, C)` | activations | one C-dimensional vector per token per sequence |
| `(B, H, T, T)` | attention scores | per head, every token's score for every other token (M1.L3) |
| `()` | the loss | a scalar: zero dimensions, one number |

Write the shape as a comment beside every line you are unsure about. Experienced practitioners do it constantly; it is the type system Python does not give you.

---

```python
import numpy as np

B, T, C = 4, 8, 16
x = np.random.randn(B, T, C)      # (4, 8, 16)  activations
W = np.random.randn(C, 3 * C)     # (16, 48)    one weight matrix
y = x @ W                         # (4, 8, 48)  @ contracts the LAST axis of x with the FIRST of W
mean = y.mean(axis=-1)            # (4, 8)      reducing an axis removes it...
mean_k = y.mean(axis=-1, keepdims=True)  # (4, 8, 1)  ...unless you keep it
centered = y - mean_k             # (4, 8, 48)  broadcasting stretches the 1
```

## Broadcasting: the one rule

The last line subtracted a `(4, 8, 1)` array from a `(4, 8, 48)` one and got `(4, 8, 48)`. That is **broadcasting**, and its rule is short enough to memorise:

1. Line the two shapes up **from the right**.
2. A missing dimension on the left counts as **1**.
3. Each aligned pair must be **equal**, or one of them must be **1**. A 1 is stretched (virtually — no copy is made) to match the other.
4. Otherwise: error.

```
   (8, 1, 6)        (5, 4)          (3,)
      (7, 1)           (4,)         (4,)
   ---------        -------        -----
   (8, 7, 6)        (5, 4)         error: 3 vs 4
```

Lab 00 has you implement this rule without numpy, which is the fastest way to make it automatic.

---

_fig 1 — adding a bias to a batch_

Components: x ((B, d_out)) · b ((d_out,)) · align right ((1, d_out)) · stretch the 1 ((B, d_out), no copy) · x + b ((B, d_out))

Steps:
1. A layer produces x with one row per example, and has one bias vector b shared by every example. The shapes differ: two dimensions against one.
2. Align from the right. b has no batch dimension, so it is treated as having size 1 there: (1, d_out). The trailing d_out matches.
3. The size-1 batch dimension is stretched to B. numpy does this with a zero stride: every row reads the same memory, nothing is copied.
4. The add is now elementwise between two (B, d_out) views, and the result is (B, d_out). In A1.L4 you will undo this stretch in the backward pass.

---

> **[segfault]** Targets `y` come out of a data loader with shape `(B,)`. Predictions come out of the model with shape `(B, 1)`. You write `loss = ((pred - y) ** 2).mean()`.
> 
> Broadcasting turns `(B, 1) − (B,)` into **`(B, B)`**: every prediction minus every target. The loss is a finite, plausible number; it even goes down a little. The model never learns the task. Lab 00's `broadcast_shape((5, 1), (5,))` returns `(5, 5)` — that is the bug, stated as a shape. Assert shapes at the boundary where data enters the loss.

## Broadcasting instead of loops

Broadcasting is not only a convenience; it is how you avoid Python loops, which run about **85 million** floating-point operations per second on the reference laptop (an Apple M5, CPython 3.12) against **2 trillion** for a numpy matmul (T0.L3). The canonical example, and lab 00's `pairwise_sq_dists`: the squared distance between every row of `X` (n, d) and every row of `Y` (m, d).

```python
diff = X[:, None, :] - Y[None, :, :]    # (n, 1, d) - (1, m, d) -> (n, m, d)
d2 = (diff ** 2).sum(axis=-1)           # (n, m)
```

`None` (or `np.newaxis`) inserts a size-1 axis exactly where you want the stretching to happen. The cost is visible in the shape: the intermediate is **n × m × d** numbers. For n = m = 10,000 and d = 768 in float32 that is 307 GB — a reason the real implementation expands `|x − y|² = |x|² − 2x·y + |y|²` and uses a matmul instead. Broadcasting removes the loop, not the memory.

**Q1. logits has shape (32, 10) and you compute logits - logits.max(axis=1). What happens?**
   A. Each row has its own max subtracted, as intended
   B. An error: (32, 10) and (32,) do not broadcast, because (32,) aligns with the 10, not the 32
   C. Each column has its own max subtracted
   D. The result has shape (32, 32)
   Answer: B — max(axis=1) returns (32,). Aligned from the right, 32 meets 10: neither is 1, so numpy raises. With keepdims=True the max is (32, 1), which stretches across the 10 columns — the stable-softmax idiom you will write in lab 02. Had the shape been (10, 10) there would be no error and each column would get the wrong row's max: the silent version of the same bug.

**Q2. A loss is computed as ((pred - y) ** 2).mean() with pred of shape (B, 1) and y of shape (B,). Training runs, the loss falls slightly, the model is useless. Why?**
   A. The learning rate is too small
   B. pred − y broadcasts to (B, B): every prediction is compared with every target, so the loss rewards predicting the batch mean
   C. mean() should be sum()
   D. Squared error cannot train a regression model
   Answer: B — (B, 1) and (B,) align as (B, 1) against (1, B) and broadcast to (B, B). The minimiser of that loss is a constant near the mean of all targets, so the loss improves a little and then stalls. The fix is to make the shapes equal — y[:, None] or pred.squeeze(-1) — and to assert it.

**Q3. How much memory does the broadcast intermediate X[:, None, :] - Y[None, :, :] need for n = 50,000, m = 1,000, d = 512 in float32?**
   A. about 100 MB
   B. about 1 GB
   C. about 102 GB
   D. none — broadcasting never allocates
   Answer: C — The stretched inputs are views, but the subtraction materialises its result: n × m × d = 2.56 × 10¹⁰ floats × 4 bytes = 102 GB. Broadcasting avoids copying the inputs; it does not avoid allocating the output.

- `np.einsum` names every axis and makes the contraction explicit: `np.einsum('btc,cd->btd', x, W)` is the `x @ W` above. M1.L3 writes attention with it.
- Strides: `x.strides` shows how many bytes to skip per step along each axis. A broadcast axis has stride 0 — that is the whole trick.

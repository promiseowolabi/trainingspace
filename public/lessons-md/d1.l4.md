# D1.L4 — Tensor Parallelism

_Track D1: Distributed Training · ~18 min · trainingspace_

> When a single layer is too big or too slow for one GPU, split its matrices. Cut the first MLP matrix by columns and the second by rows, and the whole block needs exactly one all-reduce — but that all-reduce happens in every layer, twice per step, which is why tensor parallelism never leaves the server.
Data parallelism and ZeRO split the **batch** and the **storage**; every rank still computes whole layers. **Tensor parallelism** (TP) splits the computation of each layer across devices, so every GPU holds and multiplies only a slice of each weight matrix. It reduces both memory and per-GPU compute per layer, and it is how one layer too large for a single device can run at all.

## The MLP, split two ways

Take the block's MLP (M1.L4): `Y = gelu(X · A) · B`, with A of shape (C, 4C) and B of shape (4C, C). On t GPUs:

1. **Split A by columns**: GPU i holds `A_i`, a (C, 4C/t) slice. Each computes `H_i = gelu(X · A_i)` — a slice of the hidden layer. GELU is elementwise, so it needs nothing from the other slices. **No communication.**
2. **Split B by rows**: GPU i holds `B_i`, the (4C/t, C) rows matching its hidden slice, and computes `Y_i = H_i · B_i` — a full-size (B, T, C) output that is a **partial sum**.
3. **All-reduce** the `Y_i`: `Y = Σ Y_i`, the exact result.

---

```python
import numpy as np
gelu = lambda z: 0.5 * z * (1 + np.tanh(0.7978845608 * (z + 0.044715 * z**3)))
X, A, B = np.random.randn(4, 8), np.random.randn(8, 32), np.random.randn(32, 8)
full = gelu(X @ A) @ B

t = 4                                                       # "GPUs"
A_cols, B_rows = np.split(A, t, axis=1), np.split(B, t, axis=0)
partials = [gelu(X @ Ai) @ Bi for Ai, Bi in zip(A_cols, B_rows)]   # no communication
print(np.allclose(sum(partials), full))                     # True — the sum is the all-reduce
```

---

The order matters. Splitting A by **rows** instead would make each GPU produce a partial *pre-activation*, and GELU of a partial sum is not a partial GELU — you would need an all-reduce before the nonlinearity as well. Column-then-row puts the only synchronisation after the second matmul.

**Attention splits the same way, by heads.** Heads are independent (M1.L3), so GPU i takes heads 4i…4i + 3: the q, k, v projections are column-parallel (each GPU computes its heads' q, k, v), attention runs locally, and the output projection is row-parallel, followed by one all-reduce. Lab 05's `split_heads` is literally the sharding axis.

So a transformer block under TP has **one all-reduce after attention and one after the MLP** in the forward pass, and the mirror-image pair in backward.

_fig 1 — the Megatron MLP on 2 GPUs_

Components: X (replicated) · gelu(X·A₁) (GPU 0, cols) · gelu(X·A₂) (GPU 1, cols) · H₁·B₁ (partial Y) · H₂·B₂ (partial Y) · all-reduce (Y = Y₁ + Y₂)

Steps:
1. Both GPUs hold the same input activations X. Each holds half of A's columns and half of B's rows — half the MLP's weights each.
2. Column-parallel first matmul: each GPU computes its own slice of the hidden layer and applies GELU locally. Nothing is exchanged.
3. Row-parallel second matmul: each GPU multiplies its hidden slice by the matching rows of B, producing a full-size but partial output.
4. One all-reduce sums the partial outputs. Every GPU now holds the exact Y — and the next layer starts from replicated activations again.

---

## Why it stays inside a server

Each of those all-reduces carries a full activation tensor: B·T·C values. For one 4,096-token sequence at C = 8,192 in bf16 that is 67 MB, four times per layer per step (two forward, two backward), times 80 layers: about **21 GB per sequence per step**, on the critical path — the next layer cannot start until the all-reduce finishes, so there is little to overlap it with.

Over NVLink at roughly 900 GB/s per GPU (D1.L1) that is tolerable; over a 50 GB/s network link it would dominate the step. So TP is almost always limited to the GPUs of one server — typically **t ≤ 8** — and combined with data parallelism or ZeRO across servers. Sequence parallelism, a refinement, additionally shards the LayerNorm and dropout activations along the sequence axis and turns each all-reduce into a reduce-scatter plus an all-gather, saving activation memory for the same traffic.

**Q1. Why is the first MLP matrix split by columns and the second by rows, rather than both by columns?**
   A. Columns are faster to transfer
   B. Column-splitting the first matmul gives each GPU a complete slice of the hidden layer, so the elementwise GELU needs no communication; row-splitting the second then turns the output into a sum of partials needing exactly one all-reduce
   C. It halves the parameter count
   D. Row-splitting is required for backward
   Answer: B — GELU(Σ partials) ≠ Σ GELU(partials), so any split that leaves the hidden layer as a partial sum forces a synchronisation before the nonlinearity. Column-then-row keeps the hidden slice exact and defers all communication to one all-reduce at the end.

**Q2. A team proposes tensor parallelism of degree 16 across two 8-GPU servers connected by 50 GB/s links. What is the main concern?**
   A. TP cannot exceed 8 by definition
   B. Every layer's activation all-reduces would cross the slow inter-server link on the critical path, so the step time would be dominated by communication; keep TP within the NVLink domain and use data/pipeline parallelism across servers
   C. The model would become less accurate
   D. Memory usage would double
   Answer: B — TP communicates activation-sized tensors several times per layer and the next layer waits for them. That works at NVLink speed and fails at network speed. The standard layout puts TP inside a server and the more communication-tolerant schemes across servers (D1.L6).

**Q3. How does tensor parallelism split multi-head attention?**
   A. By sequence position
   B. By heads: each GPU computes q, k, v and attention for a subset of heads (column-parallel projections), then the row-parallel output projection and one all-reduce combine them
   C. By layers
   D. It cannot be applied to attention
   Answer: B — Heads are independent computations, so they are the natural sharding axis: no head needs another head's keys or values. The pattern is the same as the MLP — column-parallel in, row-parallel out, one all-reduce.

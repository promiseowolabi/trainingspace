# T0.L1 — What Training Is

_Track T0: The Training Contract · ~20 min · trainingspace_

> A model is a function with knobs. Training is four lines in a loop — run it, score it, ask each knob which way is downhill, nudge it — repeated until the score stops improving.
Strip the vocabulary off any training run — a 7-billion-parameter language model, a fraud classifier, the line of best fit in a spreadsheet — and the same four steps are left:

1. **Forward.** Run the model on some inputs and get its predictions.
2. **Loss.** Score the predictions against the right answers with one number: how wrong, on average.
3. **Backward.** For every knob (parameter) in the model, work out which direction makes the loss smaller, and how strongly the loss responds. That vector of sensitivities is the **gradient**.
4. **Step.** Move every parameter a small distance in the downhill direction.

Repeat until the loss stops falling. Everything else in this course — autograd, Adam, attention, bf16, ZeRO, DPO — is either a better way to do one of those four steps, or a way to do them on more data, faster, with less memory.

---

```python
for batch in data:
    predictions = model(batch.inputs)            # 1. forward
    loss = loss_fn(predictions, batch.targets)   # 2. loss
    grads = gradient(loss, model.parameters)     # 3. backward
    for p, g in zip(model.parameters, grads):    # 4. step
        p -= learning_rate * g
```

---

_You already run this loop_

- **a load test tuning a connection pool** (change the pool size, rerun, read p99, keep the change if p99 fell) ≡ **one training step** (change the weights, rerun the batch, read the loss, keep the change because the gradient promised it would fall)
- **p99 latency** (one number that summarises how bad things are) ≡ **the loss** (one number that summarises how wrong the predictions are)
- **a flame graph** (which function is responsible for how much of the time) ≡ **the gradient** (which parameter is responsible for how much of the loss — and in which direction)

---

The difference from your load test is step 3. You find out which way to turn a pool-size knob by trying both directions. A model has millions of knobs; trying each one both ways would cost two forward passes per parameter per step. The gradient gives you **all of them at once**, for roughly the price of one extra forward pass. A1 is about how.

## The smallest model there is

Before a model with billions of knobs, watch one with **two** learn, step by step, with nothing but arithmetic. Every number below can be checked with a calculator.

### Step 1 — the data

Three points:

| x | y (the right answer) |
|---|---|
| 1 | 3 |
| 2 | 5 |
| 3 | 7 |

You can probably spot the rule already: **y = 2x + 1**. The point of the exercise is to watch the computer *discover* the 2 and the 1 without being told.

### Step 2 — the model

The model is a straight line:

```
prediction = w · x + b
```

It has two knobs. **w** sets how steep the line is (it should end up at 2); **b** slides the line up or down (it should end up at 1). Training means finding good values for w and b. A language model is the same idea with billions of knobs instead of two.

### Step 3 — start with a bad guess

Set both knobs to zero: w = 0, b = 0. Then every prediction is 0 × x + 0 = 0:

| x | right answer | prediction | error = prediction − answer |
|---|---|---|---|
| 1 | 3 | 0 | −3 |
| 2 | 5 | 0 | −5 |
| 3 | 7 | 0 | −7 |

A negative error means the prediction is too **low**.

---

### Step 4 — score it with one number: the loss

We want a single number that says "how wrong is the model overall". Two decisions:

1. **Square each error.** This makes every error positive (so a −5 and a +5 can't cancel out to "perfect") and makes big misses count much more than small ones (an error of 7 costs 49, not 7).
2. **Average them**, so the score doesn't depend on how many points there are.

```
squares:   (−3)² = 9     (−5)² = 25     (−7)² = 49
sum:       9 + 25 + 49 = 83
average:   83 ÷ 3 = 27.67
```

That average is the **loss** — here, **27.67**. This particular recipe is called **mean squared error**. Lower is better; 0 would mean every prediction is exactly right. **Everything training does is aimed at pushing this one number down.**

### Step 5 — which way should each knob move? The gradient

Now the key question: *if I nudge a knob up a tiny bit, does the loss go up or down — and by how much?*

**The slow way, by experiment.** Nudge w from 0 to 0.001 and recompute the loss: it becomes 27.644, a drop of 0.0227. So the loss falls by about 22.7 for every 1 unit of w — at least for small moves. Nudge b to 0.001 instead and the loss drops by 0.0100: about 10 per unit of b. Those two rates are the **gradient**: one number per knob.

**The fast way, by formula.** For this loss there is a shortcut that gives both numbers without any nudging (A1.L1 derives it):

```
for w:  (2/3) × Σ (error × x)
for b:  (2/3) × Σ (error)
```

Σ just means "add these up over the three points". Fill in the errors from step 3:

```
for w:  error × x  →  (−3 × 1) + (−5 × 2) + (−7 × 3)  =  −3 − 10 − 21  =  −34
        × 2/3      →  −34 × 2/3  =  −22.67

for b:  errors     →  −3 − 5 − 7  =  −15
        × 2/3      →  −15 × 2/3  =  −10.00
```

The same −22.67 and −10 the experiment found. In practice frameworks use the fast way — the slow way needs a separate experiment for every knob, which is hopeless with billions of them.

---

> **[info]** - **Why multiply by x for w?** w's effect on a prediction is multiplied by x: changing w by 1 moves the prediction for x = 3 by 3, but the prediction for x = 1 by only 1. So points with a bigger x have more say in which way w should move. b moves every prediction by the same amount, so its formula just adds up the errors.
> - **Why the 2?** It comes from squaring. If an error grows a little, its square grows about **twice the error** times that little bit — for example 7² = 49 but 7.01² = 49.14, an increase of 0.14 = 2 × 7 × 0.01.
> - **Why divide by 3?** Because the loss is an *average* over three points.
> - **How to read the sign.** Both numbers are **negative**: increasing the knob makes the loss go **down**. A positive number would mean the opposite. The size says how strongly the loss cares — right now w matters about twice as much as b.

---

### Step 6 — take a small step downhill

Move each knob a little in the direction that lowers the loss. How big is "a little" is set by the **learning rate** — here, 0.05:

```
new knob = old knob − learning rate × gradient

new w = 0 − 0.05 × (−22.67) = 0 + 1.133 = 1.133
new b = 0 − 0.05 × (−10.00) = 0 + 0.500 = 0.500
```

The minus sign is what makes it "downhill": a negative gradient means *increase* the knob, a positive one means *decrease* it.

### Step 7 — check that it helped

With w = 1.133 and b = 0.5, predict again:

| x | right answer | prediction = 1.133·x + 0.5 | error |
|---|---|---|---|
| 1 | 3 | 1.633 | −1.367 |
| 2 | 5 | 2.767 | −2.233 |
| 3 | 7 | 3.900 | −3.100 |

```
loss = (1.367² + 2.233² + 3.100²) ÷ 3 = (1.87 + 4.99 + 9.61) ÷ 3 = 5.49
```

**27.67 → 5.49 in one step.** The errors are still negative (still too low), but much smaller.

### Step 8 — repeat

Run steps 3 to 7 again from the new knobs. The second gradient uses the new errors:

```
for w:  (−1.367 × 1) + (−2.233 × 2) + (−3.100 × 3) = −15.13,   × 2/3 = −10.09
for b:  −1.367 − 2.233 − 3.100 = −6.70,                         × 2/3 = −4.47

new w = 1.133 + 0.05 × 10.09 = 1.638
new b = 0.500 + 0.05 × 4.47  = 0.723      →  loss 1.09
```

Notice the gradients got **smaller** (−10.09 instead of −22.67): the model is closer to right, so there is less to fix, so the steps shrink on their own. Keep going and the loop settles on the answer:

---

- **27.67** — loss at step 0 (w = 0, b = 0: every prediction is 0)
- **5.49** — after 1 step (w = 1.13, b = 0.50)
- **1.09** — after 2 steps (w = 1.64, b = 0.72)
- **0.0011** — after 10 steps (w = 2.04, b = 0.91 — close to the true 2 and 1)

---

By step 10, w ≈ 2.04 and b ≈ 0.91 — almost exactly the rule y = 2x + 1 that we never told it. The four moves are the same every time: **predict → score → gradient → step**. Notice two things.

**The loss falls fast, then slowly.** Most of the improvement is in the first few steps; after step 10, `w` and `b` crawl towards 2 and 1 because the gradient — the slope — is nearly flat near the bottom. Every real loss curve has this shape.

**The learning rate is not a detail.** Redo step 6 with a learning rate of 0.2 instead of 0.05: w jumps to 0.2 × 22.67 = 4.53 and b to 0.2 × 10 = 2. The new predictions are 6.53, 11.07 and 15.60 — now far too **high**, with errors of +3.53, +6.07 and +8.60, and the loss *rises* from 27.67 to **41.08**. The step overshot the answer. The next gradient is bigger (the errors are bigger), so the next overshoot is bigger again: after 20 steps the loss is **50,640**, and at 0.3 it is about **2 × 10¹⁵**. This is **divergence**, the first failure mode you will meet in a real run (P1.L6). Too small a learning rate is safe but slow; too large never arrives.

The same loop, in twelve lines of Python, if you want to run it yourself:

---

```python
xs, ys = [1, 2, 3], [3, 5, 7]
w, b, lr = 0.0, 0.0, 0.05

for step in range(11):
    preds = [w * x + b for x in xs]                                  # forward
    loss = sum((p - y) ** 2 for p, y in zip(preds, ys)) / len(xs)    # loss
    dw = 2 / len(xs) * sum((p - y) * x for p, y, x in zip(preds, ys, xs))
    db = 2 / len(xs) * sum(p - y for p, y in zip(preds, ys))         # backward
    print(f"step {step:2}  w={w:.3f}  b={b:.3f}  loss={loss:.4f}")
    w -= lr * dw                                                     # step
    b -= lr * db
```

---

_fig 1 — one training step_

Components: parameters (w, b) · forward (preds = w·x + b) · loss (mean (pred − y)²) · data (x, y) · backward (dL/dw, dL/db) · step (p −= lr · g)

Steps:
1. Forward: the current parameters turn inputs into predictions. Nothing is learned here; this is just running the function.
2. Loss: predictions are compared with the targets from the data and collapsed into one number — mean squared error for this model.
3. Backward: the gradient says, for each parameter, how much the loss changes per unit nudge, and in which direction. One number per parameter.
4. Step: every parameter moves against its gradient by learning-rate × gradient. Then the loop starts again with the updated parameters.

## From two knobs to billions

A language model runs the identical loop. What changes is the size of every box:

| | the line | a small GPT (capstone) | a 7B model |
|---|---|---|---|
| parameters | 2 | ~5 million | 7 × 10⁹ |
| one example | a number | 256 tokens of text | 4,096+ tokens |
| loss | squared error | cross-entropy over the vocabulary (O1.L2) | same |
| backward | by hand | autograd (A1) | autograd, sharded over GPUs (D1) |
| step | `p -= lr * g` | AdamW with a schedule (O1.L3–L4) | same, in mixed precision (P1.L3) |

Each row of that table is a track of this course. The loop is the contract they all honour.

---

> **[warning]** The loss measures how wrong the model is **on the data you score it on**. A model with enough knobs can drive training loss towards zero by memorising the training set and still be useless on anything new. That is why every real run holds some data back and reports a **validation loss** as well (O1.L6). The line above has two knobs and three points, so it cannot memorise — your GPT can.

**Q1. A run's loss goes 2.1, 1.8, 3.9, 47, 9.1e5, nan over its first five logged steps. What is the most likely cause, and the first thing to change?**
   A. The model is too small — add layers
   B. The learning rate is too large — each step overshoots and the overshoot grows; lower it
   C. The data is shuffled badly — reshuffle
   D. The loss function is wrong — switch to mean absolute error
   Answer: B — Loss that falls briefly and then grows geometrically is divergence: each step overshoots further, so the next gradient is bigger. The line in this lesson does exactly that at lr 0.2. Adding layers or changing the loss does not stop an oversized step; lowering the learning rate (and, later, warmup and clipping) does.

**Q2. Why do frameworks compute gradients instead of nudging each parameter up and down and measuring the loss?**
   A. Nudging is less accurate
   B. Nudging needs two forward passes per parameter per step — billions of passes for a large model — while the gradient for all parameters costs about one extra pass
   C. Gradients work only for neural networks
   D. Nudging cannot handle negative numbers
   Answer: B — The nudge method (finite differences) is perfectly accurate enough to check gradients with (A1.L5), but its cost scales with the number of parameters. Reverse-mode autograd returns every partial derivative for a small constant multiple of one forward pass, which is the only reason training large models is feasible.

**Q3. Your training loss is 0.02 and still falling, but validation loss has risen for the last three evaluations. What is happening?**
   A. The model is still learning — keep going
   B. The learning rate is too low
   C. The model has started memorising the training set: training loss no longer predicts performance on new data
   D. Validation loss is computed incorrectly; ignore it
   Answer: C — Training loss measures fit to examples the model has seen. When it keeps falling while validation loss rises, the extra fit is memorisation, not learning. Stopping, regularising or adding data are the responses (O1.L6); "keep going" makes it worse.
